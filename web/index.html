Reference

How it works

A static page, your broker, and one begin() call in the sketch.

01

Enable telemetry in firmware

Copy the monitor config, edit Wi-Fi and broker settings, then call begin() once in setup(). No loop() changes are required; the monitor runs in its own FreeRTOS task.

#include <NodeMonitor.h>

void setup() {
  Serial.begin(115200);
  NodeMonitor::getInstance().begin(
      "YOUR_WIFI", "YOUR_PASSWORD",
      "broker.emqx.io", 1883);
  // ... existing mesh setup ...
}

For TLS or a custom node ID use the MonitorConfig overload. The MAC address supplies a stable node ID by default.

02

Point the dashboard at the same broker

Open Connection settings and enter a browser-reachable MQTT WebSocket URL. For the public EMQX quick-test broker the default is:

wss://broker.emqx.io:8084/mqtt

Firmware uses TCP port 1883; browsers use WebSocket 8084 (TLS). They are separate listeners on the same broker.

03

Publish the dashboard

The web/ folder is fully static. Push it to GitHub and let the included Pages workflow deploy it, or open index.html locally.

GitHub Pages is HTTPS, so the broker must offer wss://. Plain ws:// is blocked as mixed content.

<prefix>/<node_id>/statusYesOnline flag, IP, board and firmware. Last Will marks the node offline.
<prefix>/<node_id>/metricsNoPacket counters, real RSSI/SNR, Wi-Fi, routes, heap and uptime.
<prefix>/<node_id>/eventsNoTX/RX, route changes, network state, errors and monitor lifecycle.
<prefix>/<node_id>/logsNoOptional raw log lines when publishRawLogs is enabled.

Monitoring vs. mesh health

The dashboard proves that telemetry arrived. It cannot prove that a LoRa radio is healthy. A node can be routing traffic while its Wi-Fi link is down, and a node with excellent Wi-Fi can have a failed radio.

Use the serial console and the mesh routing table for radio-level diagnosis.

Data stays in the browser

No backend, no database, no analytics. Settings live in localStorage; history and events live in memory and disappear on reload.

Public brokers are public. Use a unique topic prefix or a private broker with authentication for real deployments.
